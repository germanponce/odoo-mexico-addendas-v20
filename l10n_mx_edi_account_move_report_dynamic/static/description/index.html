¿Qué hace este módulo?

Permite seleccionar dinámicamente el reporte QWeb-PDF a utilizar al imprimir o enviar facturas, configurándolo por diario contable. Incluye cuatro estilos de factura/pago CFDI 4.0 y el nuevo Reporte de Factura Transporte (Carta Porte 3.1) con su anexo de condiciones de servicio.

Dependencias: account, stock, sale, sale_stock, sale_management, l10n_mx_edi (Enterprise). Migrado de Odoo 17 a Odoo 19. Compatible con CFDI 4.0 y Carta Porte 3.1.

Factura Transporte CFDI (Carta Porte 3.1) — NUEVO

Reporte especializado para empresas de autotransporte federal. Lee el complemento Carta Porte 3.1 directamente del XML firmado del CFDI.

Sección Origen / Cliente
Lee nodo Ubicacion TipoUbicacion="Origen": domicilio, RFC remitente, FechaHoraSalida. Fallback a datos de la empresa si no hay Carta Porte.
Sección Destino / Operador-Vehículo
Lee Ubicacion TipoUbicacion="Destino". Lee AutotransporteFederal: PermSCT, ConfigVehicular, Placas, PesoBruto, Seguros, Remolques. Lee FiguraTransporte tipo 01 (operador).
Bultos / Mercancias
Tabla de líneas de factura (Bultos). Tabla Mercancias del nodo CartaPorte31: PesoBrutoTotal, UnidadPeso, NumTotalMercancias y detalle por mercancía (Cantidad, Descripcion, PesoEnKg, MaterialPeligroso).
Información CFDI + Totales
Forma pago, Método pago, Moneda, Tipo cambio, Uso CFDI, Régimen Fiscal. Totales fiscales via account.document_tax_totals. Cantidad con letra.
Leyenda Pagaré + Firmas
Texto legal del pagaré mercantil. Espacio para "Recibimos de conformidad" y "Firma Transportista".
QR + Sellos + ANEXO
Código QR, Sello emisor, Sello SAT, Cadena Original. Después del QR: Anexo completo de 15 condiciones de prestación de servicios de Carta Porte (NOM-012-SCT-2-2017).

🐍 Modelos Python

account.move.send

Sobreescribe _prepare_invoice_pdf_report para seleccionar el reporte según el diario.

  • ✓ Si journal_id.cfdi_report_id está configurado → usa ese reporte
  • ✓ Si no → usa account.account_invoices (estándar Odoo)
  • ✓ Compatible con flujo de envío de correo de Odoo 19

account.journal

Agrega campo cfdi_report_id (Many2one a ir.actions.report).

  • ✓ Dominio filtrado a reportes de account.move tipo qweb-pdf
  • ✓ Visible en el formulario del diario (antes del notebook)
  • ✓ Opcional — si vacío usa el reporte predeterminado

account.move

Agrega el método get_tipo_cambio() para usar en reportes QWeb.

  • ✓ Retorna 1.0 si moneda == moneda empresa
  • ✓ Usa invoice_date o date como referencia
  • ✓ Llama a currency._convert() con round=False

account.move.line

Agrega get_taxes_line_details() para el detalle de impuestos en cada línea del reporte.

  • ✓ Retorna lista: [nombre, factor, base, tasa, importe]
  • ✓ Usa TAX_TYPE_TO_CFDI_CODE: isr→001, iva→002, ieps→003
  • ✓ Soporta facturas y notas de crédito (is_refund)

sale.order

Agrega campos logísticos usados en el reporte EST-01.

  • ✓ via_embarque (Char) — Vía / modo de transporte
  • ✓ no_orden (Char) — Número de orden del cliente

🔄 Cambios de Migración v17 → v19

models.py → 5 archivos separados

El archivo único models.py de v17 se dividió en archivos independientes por modelo, siguiendo las buenas prácticas de Odoo 19. Cada clase en su propio archivo.

AccountMoveSend — método actualizado

En v17 _prepare_invoice_pdf_report era en AccountMoveSend(TransientModel). En v19 se hereda de AbstractModel (account.move.send), que es como lo maneja Odoo 19 Enterprise.

get_tipo_cambio() — simplificado

El método v17 iteraba con for rec in self. En v19 usa ensure_one() y accede directamente a self, eliminando el bucle innecesario.

t-raw → t-out

En Odoo 19 el atributo QWeb t-raw fue eliminado y reemplazado por t-out con sanitización automática. Todos los t-raw en los reportes deben actualizarse a t-out.

werkzeug.urls eliminado

El import from werkzeug.urls import url_encode fue removido del código ya que no se usaba. En Odoo 19 usar from urllib.parse import urlencode si se necesita.

Versión 19.0.2.0.0

El manifiesto actualiza version a 19.0.2.0.0, quita el key obsoleto qweb y actualiza depends eliminando sale_stock como dependencia redundante (ya incluida por sale).

⚙️ Configuración y Uso

1
Instalar el módulo
Asegurarse de que l10n_mx_edi (Enterprise) esté instalado. Instalar l10n_mx_edi_account_move_report_dynamic desde Aplicaciones.
2
Configurar el diario
Ir a Facturación/Contabilidad → Configuración → Diarios. Abrir el diario de ventas. En el campo Reporte CFDI seleccionar el reporte deseado (EST-01, EST-02 o Carta Porte 3.1).
3
Imprimir / Enviar factura
Al confirmar y enviar una factura, el sistema detecta el reporte configurado en el diario y genera el PDF automáticamente con ese estilo. También disponible desde el botón Imprimir en la factura.
⚠
Reporte Transporte — Requisito Carta Porte firmada
El reporte de Transporte lee el nodo XML del CFDI firmado (cfdi_node). Para que los datos de Origen, Destino, Operador y Vehículo aparezcan, la factura debe tener el complemento Carta Porte 3.1 timbrado por el PAC. Si la factura aún no está timbrada, los campos mostrarán los datos generales de la empresa/receptor como fallback.
